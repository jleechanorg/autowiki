## Executive Summary

Replace `generate_mock_quality_score()` in `train_gnn.py` with actual benchmark quality scores from `run_hard_benchmark.py`'s 6-dim rubric (`score_single_output()`). The P14 checkpoint already contains per-query, per-mode scores that can drive supervised training of the GNN topology generator.

**Recommendation**: Option A (offline JSONL collection) — train GNN on existing P14 benchmark scores. The GNN learns topology-quality correlations even though the P14 "GNN mode" outputs were produced by an LLM router rather than the GNN class itself.

---

## 1. Architecture Decision: How Real Scores Get to Training

### Options Considered

| Option | Training Signal Source | Speed | Reproducibility | Correctness |
|--------|------------------------|-------|-----------------|-------------|
| **A: Offline JSONL** | P14 checkpoint scores | Slow (one-time collection) | High (fixed dataset) | Uses LLM-router topologies |
| **B: Online training** | Real-time `score_single_output()` | Fast (per-sample) | Low (non-deterministic) | Requires re-benchmarking GNN |
| **C: Hybrid** | JSONL collection + re-benchmark iteration | Medium | Medium | Iteratively improved |

### Recommendation: **Option A — Offline JSONL Collection**

**Justification**:
- **Simplicity**: No changes to `run_hard_benchmark.py`. No need to wire real GNN into the benchmark loop.
- **Speed**: P14 checkpoint exists now. JSONL can be extracted in minutes. Online training would require re-running the full benchmark.
- **Sufficient quality**: The GNN can learn which topology *structures* (node counts, edge density, sparsity) correlate with higher quality scores — even if the topologies came from an LLM router. The GNN's internal representation of "good topology patterns" will still improve.
- **Separation of concerns**: Training data collection (`--collect`) is separate from training (`--train`). Easier to debug, version, and replay.

**Limitation accepted**: P14 "GNN mode" scores reflect LLM-router output quality, not GNN-generated topology quality. This means the GNN is trained on *outputs* whose topologies were not generated by the GNN. After training, the GNN will select topologies similar to those that LLM routing produced for high-scoring queries. This is still useful signal — the GNN learns "what topology patterns tend to produce good research outputs."

**If higher fidelity needed**: Re-run benchmark with real GNN class wired into `run_gnn_mode()` (future work, out of scope for this design).

```python
def compute_reward(sparsity: float, quality_score: float, tokens: int) -> float:
    """
    Compute reward for the GNN optimization.
    Reward = (quality_score * sparsity) / log(tokens+1)
    """
    token_penalty = np.log(max(tokens, 1) + 1)
    reward = (quality_score * sparsity) / token_penalty
```

### 2.3 New File: `collect_benchmark_data.py` — Full Implementation

```python
#!/usr/bin/env python3
"""
Collect training samples from benchmark checkpoint.

Extracts (query, quality_score) pairs from the GNN mode scores
and writes them to JSONL for offline GNN training.

Usage:
    python collect_benchmark_data.py --checkpoint PATH --output PATH --benchmark-id ID
    python train_gnn.py --collect --checkpoint PATH --output PATH --benchmark-id ID
"""

import json
import os
import sys
import argparse
from typing import Dict, List


def collect_from_checkpoint(checkpoint_path: str, output_path: str,
                            benchmark_id: str = "p14") -> int:
    """
    Extract GNN-mode samples from benchmark checkpoint.

    Args:
        checkpoint_path: Path to benchmark checkpoint.json
        output_path: Path to write JSONL training data
        benchmark_id: Identifier for this benchmark run (for provenance)

    Returns:
        Number of samples collected
    """
    with open(checkpoint_path, 'r') as f:
        data = json.load(f)

    results = data.get("results", [])
    samples = []

    for query_result in results:
        query = query_result.get("query", "")
        gnn_mode = query_result.get("modes", {}).get("gnn", {})

        if "scores" not in gnn_mode:
            print(f"  WARNING: No scores for query '{query[:50]}...', skipping")
            continue

        scores = gnn_mode["scores"]
        tokens = gnn_mode.get("tokens", 0)
        output_length = gnn_mode.get("output_length", 0)

        sample = {
            "query": query,
            "quality_score": scores.get("overall", 5.0),
            "factual": scores.get("factual", 5.0),
            "comprehensive": scores.get("comprehensive", 5.0),
            "clarity": scores.get("clarity", 5.0),
            "useful": scores.get("useful", 5.0),
            "specific": scores.get("specific", 5.0),
            "tokens": tokens,
            "output_length": output_length,
            "source": "checkpoint",
            "benchmark_run_id": benchmark_id,
            # Topology is not stored in checkpoint — GNN will generate its own
            # during training based on the query. This is the key limitation:
            # the GNN learns "query -> quality_score" mapping, not
            # "specific_topology -> quality_score". See DESIGN-real-training.md.
        }
        samples.append(sample)

    os.makedirs(os.path.dirname(output_path) or ".", exist_ok=True)
    with open(output_path, 'w') as f:
        for sample in samples:
            f.write(json.dumps(sample) + "\n")

    return len(samples)


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--checkpoint",
                        default="/Users/jleechan/Downloads/chimera/benchmark_logs/checkpoint.json")
    parser.add_argument("--output",
                        default="/Users/jleechan/Downloads/chimera/training_data/p14_gnn_training.jsonl")
    parser.add_argument("--benchmark-id", default="p14_2026-04-20")
    args = parser.parse_args()

    count = collect_from_checkpoint(args.checkpoint, args.output, args.benchmark_id)
    print(f"Collected {count} samples -> {args.output}")
```

```
|  - gnn.scores          |     |  in checkpoint         |     |  quality_score,        |
|  - gnn.tokens          |     +------------------------+     |  factual/comprehensive/|
|  - gnn.output_length   |                                   |  clarity/useful/        |
+------------------------+                                   |  specific, tokens       |
                                                                +------------------------+
                                                                           |
                                                                           v
+------------------------+     +------------------------+     +------------------------+
|  chimera/gnn.py        | <-- |  train_gnn.py          | --> |  GNNTrainer.train()    |
|                        |     |  --real-data           |     |                        |

|                        |     |       v                |     |  4. backprop           |
|  + gnn_trained.pt      |     |  Samples:             |     |  5. optimizer.step()   |
|    (output weights)    |     |  {query, quality_score}|     |                        |
+------------------------+     |  topology generated   |     +------------------------+
                                |  fresh each epoch     |              |
                                |  from GNN (not stored |              v
                                |  in JSONL)           |     +------------------------+
                                +------------------------+     |  gnn_trained.pt        |
                                                                  |  (trained weights)     |
                                                                  +------------------------+

Reward computation (inside train_gnn.py):
  reward = (quality_score * sparsity) / log(tokens + 1)
  where:
    quality_score = sample["quality_score"]  (from P14 benchmark, real 6-dim overall)
    sparsity      = topology["sparsity"]      (GNN-generated, changes each epoch)
    tokens        = topology["estimated_tokens"] (GNN-generated, changes each epoch)
```

**Key point**: The JSONL contains `(query, quality_score)` pairs. The GNN topology for each sample is **regenerated fresh** during each training epoch via `gnn.generate_topology(query)`. This means:
- The GNN learns which *kinds of queries* produce which quality scores
- The GNN's topology generation is refined by gradient descent on the reward signal
- Over epochs, the GNN learns to generate topologies that maximize quality_score for similar queries

## 7. Key Risk: LLM Router vs Real GNN

### Risk Description

The audit found that `run_gnn_mode()` (run_hard_benchmark.py lines 202-282) **does not call `GNNTopologyGenerator.generate_topology()`**. Instead, it uses an LLM prompt to simulate routing:

```python
# run_hard_benchmark.py line 227
routing = call_minimax([{"role": "user", "content": routing_prompt}], ...)
```

The "GNN mode" outputs in P14 benchmark are produced by an LLM router, not by the GNN class.

**Consequence**: The P14 scores reflect the quality of LLM-router-generated agent topologies, NOT GNN-generated topologies.

### Decision: Train on LLM-router scores (Option A)

**Chosen approach**: Use the P14 scores as-is. The GNN learns "for queries similar to these benchmark queries, what overall quality score results" — even though the topologies that produced those scores were generated by an LLM.

**Why this is acceptable**:
1. The GNN's learnable signal is the *query → topology* mapping. Queries that got high scores had topologies selected by the LLM router. The GNN will learn to approximate "what topology patterns look like for high-quality queries."
2. The alternative (re-benchmarking with real GNN) costs 8+ hours of API time and requires wiring the GNN into `run_gnn_mode()` — a significant change to the benchmark pipeline.
3. The GNN's internal representation improves regardless of whether the training signal came from LLM routing or GNN routing. The topology patterns the GNN learns to produce will still be shaped by which patterns correlated with high quality scores.

**Future work (out of scope)**:
- Option B (correct but expensive): Wire real `GNNTopologyGenerator` into `run_gnn_mode()` and re-run full benchmark
- Option C (hybrid): Train on P14 → re-benchmark with new weights → retrain on fresh data

### If LLM-router mismatch is unacceptable

Do not use this design. Instead:
1. Modify `run_gnn_mode()` to call `GNNTopologyGenerator.generate_topology()` instead of the LLM router prompt
2. Store the generated topology alongside the scores in checkpoint
3. Re-run the full benchmark
4. Train with actual (topology, quality_score) pairs

This is the "correct" training signal but costs 8+ hours of API time.

## 8. Summary of Design Decisions

| Decision Point | Choice | Rationale |
|---|---|---|
| Collection strategy | Option A (offline JSONL) | Simplicity, separation of concerns |
| Quality score source | P14 checkpoint `scores["overall"]` | Available now, real 6-dim rubric |
| Training signal origin | LLM-router outputs (not real GNN) | Available; real GNN benchmark deferred |
| CLI design | `--collect` + `--real-data` as modes | Orthogonal, debuggable |
| Mock function | Deleted | Replaced by clear error message |
| Topology data in JSONL | Not stored (regenerated at training time) | P14 checkpoint doesn't have it; acceptable for Option A |
